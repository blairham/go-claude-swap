# Security Policy

## What cswap can do

cswap manages Claude Code logins. It runs **as you**, and everything it
holds is a credential for one of your Claude accounts.

- **The live login.** On macOS cswap reads and replaces the Keychain item
  Claude Code uses (`Claude Code-credentials`), through `/usr/bin/security`
  pinned by path (never `PATH`), so the Keychain's access-control entry
  stays tied to that binary. Elsewhere the live login is
  `~/.claude/.credentials.json`. Only the `oauthAccount` object in
  `~/.claude.json` is rewritten on a switch; every other key is left as it
  was.
- **Account backups.** On macOS each account's credential is a Keychain
  item. Without a usable Keychain (Linux, WSL, `CSWAP_DISABLE_KEYCHAIN=1`)
  it is a `.enc` file under the backup root. **`.enc` is base64, not
  encryption** — the same format as the Python claude-swap, for
  compatibility. Its protection is the file mode: cswap writes every file in
  the backup root `0600` and its directories `0700`. The backup root is
  `~/.claude-swap-backup` on macOS and
  `${XDG_DATA_HOME:-~/.local/share}/claude-swap` on Linux.
- **`cswap export` is not encrypted.** By default it writes the
  account-specific part of each credential, `--full` the whole blob, in
  plain JSON. Treat the file as the credentials it is; pipe it through
  `gpg` (or similar) to move it between machines.
- **Network.** cswap talks to Anthropic only, over TLS verified against the
  system roots: `platform.claude.com` to refresh a token or finish a
  `cswap login`, and `api.anthropic.com` for usage and profile reads.
  Tokens are sent to those endpoints and nowhere else.
- **The control socket.** A running `cswap auto` serves a gRPC API on a
  unix socket in the backup root, mode `0600`, so only your user can reach
  it. It reports status and switch events and can wake the loop; it never
  returns a credential.
- **The service.** `cswap service install` writes a launchd LaunchAgent
  (macOS) or a systemd user unit (Linux) that runs `cswap auto` as you;
  `brew services start cswap` does the same through Homebrew. It is a user
  service on purpose: the Keychain needs your login session.
- **`cswap run`** gives a terminal its own Claude Code profile under
  `<backup root>/sessions/`, seeded from an account's backup. Claude Code
  refreshes the token inside it, and cswap copies a newer token back into
  the backup only while no session is running.

## Supported versions

cswap is pre-stable (`v0.x`). Only the latest release receives fixes.

## Verifying a release

Releases after v0.4.0 are signed with
[cosign](https://github.com/sigstore/cosign) keyless signing: the signature is
tied to the GitHub Actions workflow that built the release, not to a key
someone could leak. `.github/workflows/release.yml` runs the shared workflow
in [blairham/.github](https://github.com/blairham/.github)
(`.github/workflows/go-release.yml`), so the signing identity is that shared
workflow; the certificate also names this repository and the tag.

**Downloads.** `checksums.txt` is signed; it lists the digest of every
archive. Verify the signature, then the archives against it:

```sh
VERSION=v0.5.0
cosign verify-blob \
  --certificate-identity-regexp '^https://github\.com/blairham/\.github/\.github/workflows/go-release\.yml@' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-github-workflow-repository blairham/go-claude-swap \
  --certificate-github-workflow-ref "refs/tags/$VERSION" \
  --bundle checksums.txt.sigstore.json checksums.txt
sha256sum --check --ignore-missing checksums.txt
```

**Provenance.** Every archive carries SLSA build provenance, generated by
[`actions/attest-build-provenance`](https://github.com/actions/attest-build-provenance)
in the release workflow and stored in the repository's attestations:

```sh
gh attestation verify cswap_Darwin_arm64.tar.gz --repo blairham/go-claude-swap \
  --signer-workflow blairham/.github/.github/workflows/go-release.yml
```

The same bundle is attached to the release as
`go-claude-swap-$VERSION.intoto.jsonl`, for checking offline:

```sh
gh attestation verify cswap_Darwin_arm64.tar.gz --repo blairham/go-claude-swap \
  --bundle "go-claude-swap-$VERSION.intoto.jsonl" \
  --signer-workflow blairham/.github/.github/workflows/go-release.yml
```

Releases up to and including v0.4.0 are unsigned and carry no provenance;
`checksums.txt` is their only integrity check.

## Reporting a vulnerability

**Do not open a public issue.** Report it privately through GitHub:
[Security → Report a vulnerability](https://github.com/blairham/go-claude-swap/security/advisories/new).

Please include the affected version or commit, what an attacker can do, and
the steps to reproduce. You should receive a response within a week.

In scope, among others:

- a token or credential written to a log (including `cswap auto --log-file`),
  `switch-history.jsonl`, the usage cache, a `--json` output, or anywhere
  but the Keychain, the live credentials file and the backup root
- a file or directory in the backup root, or a session profile, created
  readable by other users
- a token sent anywhere but Anthropic's endpoints, or over a connection that
  skips TLS verification
- the control socket returning a credential or reachable by another user
- a switch, refresh or import that destroys a credential instead of stashing
  it (`cswap unclaimed`)
- an account name, alias, email or path from `sequence.json`,
  `mappings.json` or an import that makes cswap write outside the backup
  root or the Claude Code config directory

Out of scope: the `.enc` backups and `cswap export` files being readable by
anyone who can already read your files as you — that is the documented
format, not a vulnerability.
